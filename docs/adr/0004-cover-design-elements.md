# ADR 0004: 表紙は mm 座標の要素リスト（cover.json）で持ち、プレビュー上で直接動かす

- 版: 0.1
- 改定日: 2026-10-17
- 状態: 提案

## 改定履歴

| 版 | 改定日 | 内容 |

## 文脈

統合版の表紙は固定レイアウト（青い帯・作成者行・収録内容）だった。ロゴや絵柄を置いたり、
文字の位置を変えたりしたいが、CSS や HTML を直接書かせるのは利用者の負担が大きい。
ドラッグで配置できる方が直感的である。

## 決定

- 表紙は **A4 1 ページ（210 × 297 mm）上の要素リスト**として `cover.json` に持つ。要素は
  `text`（プレースホルダ `{title}` `{subtitle}` `{author}` `{date}` `{version}` `{count}` を展開）、
  `image`（`images/` の PNG は data URI、SVG はインライン）、`rect`（帯）、`contents`（収録内容）、`notes`（補足）。
  位置 `x` `y` と幅 `w`（高さ `h` は任意）は **mm** で持ち、印刷座標と一致させる
- `cover.json` が無ければ従来と同じ見た目の既定デザイン（`defaultCoverDesign`）を使う
- 印刷では表紙だけ `page: cover` の名前付きページ（`@page cover { margin: 0 }`）にして、画面と同じ座標で出る
- エディタでは章一覧の先頭に「表紙」行を置き、ソース＝`cover.json`、HTML＝生成結果、プレビュー＝ドラッグ可能な表紙。
  要素の移動と右下のつまみでの幅変更は親ページ側のイベントハンドラで行い（iframe は `allow-same-origin` のみ）、
  確定時に 0.5 mm 単位に丸めて `cover.json` に書き戻す。色や文字サイズはソースで編集する
- 書き出し時は編集用属性（`data-el`）を付けない

## 結果

- 利点: 表紙の自由度が上がり、ロゴ・絵柄を置ける。JSON なので CLI でも同じ表紙が出る。位置が mm なので印刷結果と一致する
- 欠点: 文字の自動折り返し量はブラウザ依存で、幅だけ指定した要素の高さは可変。要素の重なり順は `z` で管理する必要がある
- 補足: ロゴは PNG から SVG に起こしたもの（マークは図形、文字は輪郭トレース）をプロジェクトの `images/` に置いて使う
