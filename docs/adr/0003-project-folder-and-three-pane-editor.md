# ADR 0003: 素材はプロジェクトフォルダに保存し、ブラウザから直接読み書きする

- 版: 0.1
- 改定日: 2026-10-17
- 状態: 提案

## 文脈

ADR 0001 の第 1 段階では、素材をその都度ブラウザに取り込み、作業状態を IndexedDB に保存していた。
運用してみると次の不便があった。

- 原稿の修正のたびに取り込み直す必要があり、原稿・画像・メニュー定義の「正」がどこにあるか曖昧になる
- マニュアルが複数あると素材が混ざる
- 原稿を見ながら出力を確認したいが、取り込み型ではエディタと出力が離れている

## 決定

1. **保存フォルダ方式**: 利用者が「保存フォルダ」（例: リポジトリの `projects/`）を 1 度選び、
   その中のサブフォルダ 1 つを 1 プロジェクト（1 マニュアル）とする。構成は Web サイトのフォルダに倣い
   `manual.json`（マニュアル情報・章の並び・グループ）、`chapters/`（.md / 手順 .json）、`images/`、
   `catalog/`（menus.json・menu-tree.txt）、`output/`（書き出した HTML）とする
2. **File System Access API** でフォルダを読み書きする（Chrome / Edge）。ハンドルは IndexedDB に記憶し、
   次回は再接続ボタンで権限を取り直す。アプリ内の編集は 0.6 秒後にファイルへ自動保存する。
   手元のエディタで直接編集してもよく、その場合は「再読込」で読み直す
3. `manual.json` は CLI の manifest と同じ形式にし、CLI（`scripts/build-cli.ts`）からも同じフォルダを
   そのまま生成できるようにする。組み立ては `src/core/project.ts` の `assembleManual()` に一本化し、
   ファイルの読み方だけを `ProjectFiles` インターフェースで差し替える
4. **3 ペインのエディタ**: ソース（Markdown / JSON、CodeMirror 6）・生成 HTML（読み取り専用）・プレビュー
   を横に並べ、スクロール位置を同期する。同期の座標は「ソースの行番号」とし、Markdown はブロックごとに
   `data-line`、手順 JSON は各手順に `data-step`（n 番目の `"text"` キーの行に対応）を出力して対応点にする。
   対応点が無い章（カタログ章）は全体の割合で同期する。これらの属性は書き出し時には付けない
5. **章番号の自動採番**: グループ名は番号なしで持ち（例: 「在庫・伝票」）、`autoNumberGroups` が有効なら
   並び順に「第N章 」を付けて出力する。章の挿入・並べ替えで番号は自動的に振り直される。
   既存の「第3章 …」という名前は先頭の番号を外して扱う

## 結果

- 利点: 素材の正がフォルダにあり Git や共有ドライブで管理できる。複数マニュアルを切り替えられる。
  編集と出力の確認が同じ画面で完結する。CLI とブラウザの出力が一致する
- 欠点: Chrome / Edge 限定（File System Access API）。CodeMirror 導入でバンドルが約 740 kB になる。
  ブラウザ保存型（旧 `storage.ts` の state ストア）は廃止し、復元しない
- 影響: `samples/` は `projects/sample/` に移した。利用者のプロジェクトは機密を含むため `projects/` 配下で
  `sample/` 以外を `.gitignore` する
